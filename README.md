## How I build

- **Local-first where possible.** Prefer useful tools with data under the user's control.
- **Cross-platform engineering.** Work across Windows, web browsers, iOS, Android and local developer tooling.
- **Verification before release.** Automated tests, CI, clear setup instructions and documented limitations.
- **Reviewable changes.** Keep improvements focused so they can be tested, reviewed and rolled back.

> Project maturity and platform support vary. See each project's README, issue tracker and CI results for current status. Automated tests do not guarantee real-device or production behavior.

## Documentation, feedback and security

Start with a project's **README** for requirements and setup, then check its **Issues**, **Pull Requests** and **Actions** tabs for current work. Some applications serve Turkish workflows and provide Turkish documentation or interfaces alongside English guides.

For a bug report, open an issue in the relevant repository with the version, environment, reproduction steps and expected versus actual behavior. **Do not post access tokens, personal data or exploitable vulnerability details publicly.**
